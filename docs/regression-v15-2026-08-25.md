# Codex PTC v15 通用 Agent 能力回归报告

- 日期：2026-08-25
- DSH：`0.1.0-rc.6`
- 控制器：`runtime-v15.mjs`
- 实测模型：`gpt-5.6-sol`，推理档位 `low`

## 目标

v14 修复了已知的外部执行场景，但按 AWS、云资源、数据库或业务对象继续扩充关键词仍然无法形成通用 Agent。新行业、新系统、新内容类型和未知架构不应先登记名称才能获得终端、API、文件编辑或验证能力。

v15 因而改为能力优先：原生模式是必须被提示词明确证明的低成本快路径，Code Mode 是未知任务的能力保底。控制器源码不包含测试中使用的 Stripe、Salesforce、CRM、ERP、FooBar、AcmeDesk 或 Zeta-42 名称。

## 路由原则

1. 明确的本地文件读取、仓库搜索、Web 调研、解释、翻译、提示词等直接回答可以使用精简原生工具面。
2. 修改、命令、测试、错误恢复、大范围聚合和实际查询/获取/调用/连接/同步等动作进入 Code Mode。
3. 无法证明属于上述原生快路径的未知或含糊任务默认进入 Code Mode；这只保留能力，不强迫模型调用工具。
4. 连续任务的“继续”、错误回报和图片跟进保持执行能力；独立的新知识问题可以降回原生模式。
5. 路由不读取仓库、凭据或业务数据，也不依赖 provider、模型、工作目录、会话标题或领域名。

## 确定性验证

`npm test`：30/30 通过。用例包括：

- 多个已知与虚构系统上的订单、客户、库存、指标、支付、工单等实际动作；
- 完全未知的 `Zeta-42` 内容处理、陌生领域任务和全新信息架构设计；
- 内容架构调整、重新规划、部署和连续执行；
- 本地代码搜索、配置文件读取、API 文档调研、架构解释、翻译、提示词和问候等原生反例；
- 断言控制器源码没有测试中的业务/供应商名称，避免按测试答案优化。

## DSH 新会话无副作用实测

同一新会话只要求模型报告可见工具，禁止调用工具、读取文件或联网。历史中没有 `tools/call` 事件。

| 回合 | 任务形态 | 请求工具 schema | 模型工具调用 |
| --- | --- | --- | ---: |
| 1 | 从未出现过的 `Zeta-42` 内容处理 | `run_code` | 0 |
| 2 | 明确“只解释”，不执行 | `read` | 0 |
| 3 | 未知内容形态的信息架构设计 | `run_code` | 0 |

这证明了未知任务保留能力、明确快路径可以降级、之后的新可执行任务可以恢复能力。它不是具体外部系统正确性或性能基准；实际任务仍需验证自己的数据、权限、网络和结果。
